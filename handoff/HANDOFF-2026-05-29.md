## Architecture

```
Chrome loads page → manifest.json injects:
  lib/token-tracker.js → lib/llm-client.js → content/form-detector.js → content/content.js

content.js = orchestrator (UI, fill logic, learning, SPA observer)
form-detector.js = engine (field detection via scoring, fill strategies)
llm-client.js = API bridge (OpenAI-compatible endpoint)
background.js = service worker (PDF extraction, LLM profile extraction, hot-reload)
```

**Fill All flow:**
```
fillPersonal() → fillExperience() → fillEducation() → fillSkills() → fillAIQuestions() → fillApplicationQuestions() → fillLearnedRadios()
```

**Key mechanism:** Oracle CX uses Knockout.js. Direct `el.value = x` succeeds in the DOM but Knockout's observable doesn't update. The extension uses:
- `fillTextInput()` in form-detector.js: For Oracle CX fields, skips DOM/native setter, goes directly to char-by-char (Strategy 3). If that throws "Illegal invocation" (combobox elements), falls through to InputEvent per-char (Strategy 4).
- `fillExpField()` in content.js: Direct char-by-char using `el.value = value.substring(0, i+1)` + `input` events. Used for experience text fields (employerName, jobTitle, city, responsibilities, country).
- `fillOracleCombobox()` in form-detector.js: DOM click → native setter + Enter → char-by-char → InputEvent. Used for comboboxes (phone, country, postal code, date pickers, education degree/school/level).

## What to Fix Next (Priority Order)

### 1. Education fields not filling (CRITICAL)

The form opens (attempt 0 succeeds, 1 tile created) but degree/school/level comboboxes remain empty. Debug steps:
- Add `console.log` before and after each `FormDetector.fillField()` call in `fillEducation()`
- Check if `document.querySelectorAll('[name="contentItemId"]')` finds elements after the form opens
- Check if `fillOracleCombobox()` is being called and which strategy it reaches
- The education comboboxes might need a different approach than experience date comboboxes

### 2. Skills section

Oracle's skill suggestion buttons mark skills as "desired" when clicked (buttons disappear). This might actually be correct behavior — the skills ARE selected, they just don't show as tiles. Verify by submitting the form and checking if skills appear on the submitted application.

### 3. Application Questions visual confirmation

The `aria-pressed` attribute stays "false" even after the Knockout observable updates. The border color changes (pink = selected). Consider checking `ko.contextFor(btn).$data.isSelected()` for a more reliable selected state check.

### 4. "Illegal invocation" on date comboboxes

The native setter `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype, 'value').set` throws on Oracle's custom combobox elements. The fallback to InputEvent works but adds ~4 extra log lines per field. Consider skipping char-by-char for comboboxes and going directly to InputEvent.

### 5. LLM endpoint

`localhost:19530` needs to be running for AI question answering. The textarea fields (work summary, custom questions) can't be filled without it.
