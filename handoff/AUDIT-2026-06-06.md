## 3. COMPREHENSIVE BUG LIST

### BUG #1: Combobox value verification fails for typeahead
**File:** `form-detector.js` — `fillOracleCombobox()` line ~707
**Issue:** After clicking a matched option via typeahead, code checks `el.value` and toggle text. But Oracle doesn't set either after typeahead click. Typeahead match clicks but confirmation check fails → falls through to slower fallbacks.
**Observation:** Skills and education comboboxes fall through to char-by-char (which works but takes ~5s per skill and doesn't activate Oracle's dropdown).
**Fix applied:** Added `aria-expanded === 'false'` check as alternative confirmation. **Needs testing on ONE field.**

### BUG #2: City field fill fails with "ALL strategies failed"
**Observation:** Trace log showed `fillField [city] → ALL strategies failed` while city data exists (Gdansk → learned to Wrocław). Needs investigation — city is a text input, should use paste strategy. Might be detection issue.

### BUG #3: Education level dropdown mapping
**Observation:** "Masters Degree" and "Bachelors Degree" don't match Oracle's dropdown options. Typeahead found 2 options but "no match". Char-by-char also failed → level stays empty.
**Fix needed:** Check actual Oracle options and add degreeMap. Example existing map: "Bachelor of Technology" → "Bachelor of Engineering".

### BUG #4: Education date fields not filling
**Observation:** Education start/end month/year remain empty. Comboboxes for dates not filling properly.
**Fix needed:** Trace logic for education date comboboxes.

### BUG #5: Experience — only 1 entry added
**Observation:** Fill All adds only 1 experience entry (CycloTech). Log says "No Add Experience trigger found — skipping". Resume has 3 experience entries.
**Fix needed:** Check the "Add Experience" trigger detection in content.js.

### BUG #6: Skills typeahead wrong match
**Observation:** "GUI" matched "Strategic Guidance" via typeahead. Matching is too loose (startsWith match on listbox options).
**Fix needed:** Stricter matching in typeahead — prefer exact match over startsWith.

### BUG #7: ISAE-SUPAERO school not in Oracle dropdown
**Observation:** Typeahead for "ISAE-SUPAERO" found 0 options in `educationalEstablishment` combobox. Char-by-char left partial "ISAE-" in field.
**Fix needed:** Fallback strategy: type full name via char-by-char and submit even if not in dropdown.

### BUG #8: addressLine1 = "Bhalla" (learned-field pollution)
**Observation:** `learned_fields.street_address = "Bhalla"` was saved from a previous incorrect fill. Now every fill puts "Bhalla" into Street Name.
**Fix needed:** Clear the learned field `street_address`. Root cause: learning system saved an incorrect value as a correction. Also needs a fix to prevent learning obviously wrong values (e.g., names in address fields).

### BUG #9: City = "Wrocław" overwrote "Gdansk"
**Observation:** `learned_fields.city = "Wrocław"` overwrote the extracted "Gdansk". This may be correct but needs verification.
**Fix needed:** Validate learned city against extracted city — flag mismatches for user review.

### BUG #10: addressLine2 = "91" from unknown source
**Observation:** Street number "91" appears in House Number field but doesn't match any stored data.
**Root cause:** Unknown. Possibly manually entered in a previous session and learned.

### BUG #11: region2 = "Dolnoslaskie" from unknown source
**Observation:** State field filled with "Dolnoslaskie" but extracted state was empty.
**Root cause:** Learning system learned it from a previous manual entry.

### BUG #12: Phone country code combobox routing
**Observation:** Phone country code combobox (role=combobox, with toggle button) routes correctly to `fillOracleCombobox`. Works ✅. But unlabeled `type="tel"` field defaults to `phone` — needs verification.

### BUG #13: Fill All is slow
**Observation:** Full Fill All takes ~90-120s. Skills section ~75s (28 skills × ~2.7s each). Each combobox tries 3 strategies (DOM → paste → char-by-char) × 5s each.
**Fix needed:** If Bug #1 is fixed, many comboboxes would succeed on DOM strategy (600ms) instead of failing through all 3.

### BUG #14: Content script isolated world issue
**Observation:** `page.evaluate()` runs in page world, can't access content script functions. Clicking F buttons via `page.evaluate()` doesn't trigger content script handlers.
**Workaround:** Use `cdc click` which uses CDP's `Input.dispatchMouseEvent` (real mouse events).

### BUG #15: JC panel buttons invisible to body scan
**Observation:** JC panel (Fill All, Clear All, ×) is appended outside `<document.body>` (extension attaches to `<html>`). `document.querySelectorAll('body *')` misses them.
**Workaround:** Extension elements should not appear in page layout anyway. Confirmed with user.
